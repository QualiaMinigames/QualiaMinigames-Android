# QualiaMinigames

[简体中文](README.md) | English

The Android front end of the minigames collection.

The rules live in [QualiaMinigames-Core](https://github.com/QualiaMinigames/QualiaMinigames-Core)
and the bindings in [QualiaMinigames-FFI](https://github.com/QualiaMinigames/QualiaMinigames-FFI);
this repository is the interface.

Five games ship: pipes (4 to 35 cells on a side, flat and wrapped), sudoku (standard 9×9, three
difficulties), minesweeper (4 to 128 cells a side, normal and no-guess), nonogram (4 to 64 cells
a side, checked for a unique answer) and hashi (4 to 35 points a side, islands joined by
bridges). Every puzzle is generated from a seed on the device; nothing is fetched.

## Layout and dependencies

This repository is one of three siblings that together make a complete build. Each is an
independent repository and none contains another:

```text
QualiaMinigames/               (workspace root, three repositories side by side)
├── Core/                      QualiaMinigames-Core (crate `qualia-minigames-core`)
├── FFI/                       QualiaMinigames-FFI (crate `qualia-minigames-ffi`)
└── Android/                   QualiaMinigames-Android (this repository)
```

`Core` → `FFI` → `Android` is a one-way dependency that cannot be split: the FFI exports the
core's types and this repository calls the FFI's interface.

**This repository contains neither of the other two and has no submodules.** A released build
depends on `qualia-minigames-ffi` from crates.io; while the FFI or the core is being changed,
either of these makes the change visible here:

```powershell
# Point at a local FFI checkout (recommended: the change is visible immediately)
./gradlew :app:assembleDebug "-Pqualia.minigames.ffi.localDir=../FFI"

# Without the property, the build downloads qualia-minigames-ffi 0.1.1 from crates.io into app/rust/
./gradlew :app:assembleDebug
```

`app/rust/` is the unpacked crate and is git ignored; deleting it re-unpacks it. Both paths
generate the Kotlin bindings from the same Rust source, so the two halves of a binding always
come from one place.

## Building

Requires JDK 21, the Android SDK (with NDK `28.2.13676358`), a Rust toolchain, and the
`cargo-ndk` and `uniffi-bindgen` tools:

```powershell
cargo install cargo-ndk --locked
cargo install uniffi --version 0.32.2 --features cli --locked
```

`local.properties` holds the SDK location and is not committed:

```properties
sdk.dir=D\:\\AndroidSdk
```

Then:

```powershell
./gradlew :app:assembleDebug      # a debug build, for verifying behaviour
./gradlew :app:assembleRelease    # a release build; needs keystore.properties
./gradlew :app:testDebugUnitTest  # unit tests, including round trips into the real Rust rules
```

The build cross-compiles the Rust library for `arm64-v8a`, `armeabi-v7a` and `x86_64`, then
generates the Kotlin bindings under `com.qiushui1012.app.minigames.ffi` from the library it
just built. Both the generated sources and the libraries live under `app/build/` and are not
committed.

## Signing

The keystore and its passwords never enter the repository. A local release build reads
`keystore.properties` in the repository root, which is git ignored:

```properties
storeFile=E:\\keys\\qualia-minigames-release.jks
storePassword=xxx
keyAlias=qualia-minigames
keyPassword=xxx
```

Without that file a release build falls back to the debug keystore and warns: it installs and
runs, but it is not an identity to publish under. CI writes the same file from repository
secrets; see `.github/workflows/`.
